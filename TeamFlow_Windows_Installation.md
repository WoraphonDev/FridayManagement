## IIS and HTTPS rehearsal

Owner installs IIS URL Rewrite and Application Request Routing (ARR) if available, enables ARR proxy and creates an inbound rewrite to `http://127.0.0.1:3000/{R:1}` preserving query strings. IIS serves as proxy; never expose data/backup/config as a virtual directory. Use one host binding and a valid HTTPS certificate; reject unknown hosts. [Microsoft ARR/URL Rewrite walkthrough](https://learn.microsoft.com/en-us/iis/extensions/url-rewrite-module/reverse-proxy-with-url-rewrite-v2-and-application-request-routing).

Set APP_ORIGIN to the HTTPS public origin with exact scheme/host/port and no path. Set TRUSTED_PROXY to exact proxy peer IPs only (e.g. 127.0.0.1 and ::1 if actually used), never wildcard/hop-count. Owner configures proxy to replace untrusted client forwarding headers with verified client IP/protocol; preserve browser Origin/Host and body. Verify spoofed forwarded headers do not expand access or evade rate limits. Disable API/login/download caching and response-body rewriting; preserve no-store, Set-Cookie, CSP and request IDs. Configure request filtering/body limits to allow a 10MiB file plus multipart overhead, without raising app's file limit. Redirect plain HTTP at proxy, validate HTTPS cookie attributes and CSRF/Origin refusals from a separate browser. Keep backend port inaccessible externally and readiness local only. Record proxy configuration and actual results without credentials. HTTPS and current/previous browser coverage remain NOT_RUN.
