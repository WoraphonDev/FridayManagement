## Technical contract proposal — รอ human specification approval

Current locked wire: API prose/OpenAPI/generator **1.15.0**, **89 routes / 120 schemas**. `GET /api/directory` operationId `get_api_directory`, `x-permission=admin_or_any_active_lead`, `x-owner-tasks=[T-021,T-024,T-069]`, `x-idempotency=none`, 200 `DirectoryPersonPage`. Legacy items require `id`, `display_name`, nullable `job_title`, `teams[{id,name}]`. ปัจจุบัน `project` เป็น unknown query → 400 INVALID_QUERY; ยังไม่มี scoped runtime

### Query และลำดับ errors ที่เสนอ

| Field / input | Exact proposal (ไม่ใช่คำตอบ technical ที่ Zo เลือกแล้ว) |
|---|---|
| `project` omitted | Legacy Admin/any existing access Lead authorization + response/search/paging เดิมทุกประการ; ไม่ตีความ missing ว่า current project หรือ global P-03 grant |
| `project` present | Optional scalar `Id`: canonical decimal integer **1..2147483647**; เพียง presence เลือก scoped mode หลัง validation ไม่ใช้ truthiness. `project=`, `0`, `-1`, `+1` (รวม URL-decoded space), `01`, `1.0`, `1e2`, `null`, whitespace, overflow, bracket/array/comma syntax → **400 INVALID_QUERY**; ไม่มี invalid→legacy fallback |
| Known scalars | `project`, `q`, `page`, `pageSize` ส่งซ้ำ **แม้ค่าเท่ากัน** → 400 INVALID_QUERY เช่น `project=1&project=1`, `q=&q=`, repeated pagination. Unknown fields รวม `username`, `team`, `includeInactive`, `project[]`, `q[]`, `sort` → 400; ไม่ strip |
| Pagination | page default1, range1..2147483647; pageSize default50, range1..100. Canonical integer decoding เหมือน project; empty/zero/noninteger/out-of-range/duplicate → 400. Order `id ASC` stable tie-breaker; page เกินท้ายคืน `items:[]` + scoped matched eligible total ไม่เปลี่ยนหน้าเอง |
| `q` | Optional string, **0..100 Unicode scalars และ ≤100 UTF16 code units** ตาม text(100). Omitted/empty string = ทุก eligible name; whitespace-only เป็น **literal search ไม่ trim** ตาม legacy behavior. ชื่อเท่านั้น ไม่ค้น username/email/job title/team. Thai/emoji ส่งด้วย URL encoding; ไม่เพิ่ม casefold/normalization contract ใหม่. `%`, `_`, `[`, backslash เป็น literal escaped LIKE search; parameterized SQL; เกิน UTF16/scalar limit → 400 |

**รักษา locked precedence ไม่สลับ auth-first:** API §6 กำหนด ingress syntax ก่อน session/resource/rights; actual `middleware.process` เรียก `queryFor` ก่อน session/password และ preflight authorization. ดังนั้น malformed/unknown/repeated query → **400 INVALID_QUERY แม้ session หาย/expired/inactive หรือ must-change-password**; path matching/ingress failures คงลำดับเดิม. สำหรับ **valid query**: missing/expired/revoked/inactive session → **401 UNAUTHENTICATED**; authenticated forced-password → **403 PASSWORD_CHANGE_REQUIRED** ก่อน project lookup; แล้ว project absent/invisible → **404 NOT_FOUND**, visible project แต่ไม่ใช่ authorized scoped actor → **403 FORBIDDEN**. Editor/Viewer+P-03 หรือ manager ไม่มี P-03 ที่ยังเห็น project =403; unrelated actor มองไม่เห็น =404; unrelated-team Lead ที่เห็น projectในฐานะ Viewer =403 ไม่ bypass ด้วย legacy Lead grant. ไม่คืน names/total/currentVersion/hidden project detail ใน errors

No new error codes/envelope. Mutation additions/precedence ระบุใน protection section; ไม่ reorder existing checks. GET ไม่มี expected membership version, Origin/CSRF หรือ idempotency key เพิ่ม; no-store/X-Request-Id และ existing busy/unavailable errors เดิม. PUT/DELETE คง current actor auth/resource/operation-rights-before-version precedence: lost visibility404/actor operation denial403 มาก่อน stale409 และ `currentVersion` ส่งเฉพาะ resource ที่ยังเข้าถึงได้; ไม่ใช้ discovery snapshot เป็น authorization/version token. Source service ตรวจ target existence (PUT ตรวจ active, DELETE ไม่ตรวจ active)/old explicit manager หลัง requireVersion อยู่แล้ว จึงไม่เสนอ reorder หรืออ้างว่า target error ทุกชนิดต้องชนะ409

### Scope, response และ compatibility ที่เสนอ

1. Scoped authorization ตรวจ active current actor/session/password, project visibility, แล้ว active Admin **หรือ owner-team access Lead** หรือ **explicit actual manager ของ project นั้น + current P-03**; job title/team_position, global key, team membership, manager ของ project อื่นไม่พอ. เสนอ directory-only `x-permission=project_scoped_candidates_or_legacy_directory` แทน marker เดิมใน operation นี้; เพิ่ม knownPermissions recognition และ explicit two-mode dispatch ใน authorizeOperation โดยไม่เปลี่ยน policy ของ operation อื่น. Absent project ใช้ exact legacy Admin/any existing access Lead predicate; present validated project ใช้ projectAccess/can ไม่ any-Lead fast path. Route preflight และ execute checks + service read guard ต้องตรงกัน, อ่าน current keys ทุก request; resolve project ก่อน count/items ทั้งคู่
2. Candidate base = active accounts ที่ใช้ Editor/Viewer selection ได้. **Proposed technical refinement:** ตัด effective Admin/owner-team Lead จาก scoped Editor/Viewer picker ทุก actor เพราะ role ที่ได้จริงไม่ใช่ Editor/Viewer; P-03 actor ตัด **explicit manager ใน project นี้** เพิ่ม รวมตนเอง. Admin/owner Lead อาจเลือก existing explicit manager เพื่อเปลี่ยนเป็น Editor/Viewer ได้เฉพาะ existing appointment/removal authority + explicit review/version confirmation เดิม. Manager ของ project อื่น และ access Lead ของทีมอื่นยัง eligible หากไม่ protected ใน project นี้. ไม่ต้องมี P-key/team membership/job title; target `must_change_password` ไม่ใช่ข้อห้าม PUT เมื่อ active. ไม่ exclude ทุก existing Editor/Viewer: PUT รองรับ add/update ตามเดิม
3. ห้าม filter ตาม hidden-team roster หรือให้ team affiliations เป็น search predicate. ใช้ identity-distinct `EXISTS`/`NOT EXISTS` เพื่อไม่ซ้ำคนที่อยู่หลายทีม; eligibility/search predicate **เหมือนกัน** สำหรับ count/page. `total` = จำนวน identities ใน approved **matched eligible pool** ของ project/actor/q นั้น **ก่อน pagination** ไม่ใช่ users ทั้งองค์กร, team/member count หรือจำนวนก่อนตัด protected targets. No query/count ก่อน authorization; no overfetch legacy rows แล้ว filter ใน browser. DB transaction/recheck ตาม provider เดิม; PG adapter ปัจจุบัน serialize application transactions ด้วย advisory lock ภายใต้ READ COMMITTED ไม่อ้างว่าเป็น SERIALIZABLE หรือกัน external DB writes ทุกรูปแบบ
4. เสนอ new named schemas **`ProjectMemberCandidate`** strict `{id:Id,display_name:nonblank(100)}` และ **`ProjectMemberCandidatePage`** strict `{items:ProjectMemberCandidate[≤100],page,pageSize,total}` ทุก field required; display_name ใช้ UTF16 rule เดิม, total integer0..2147483647. ไม่มี job_title/teams/team IDs/names/counts/username/email/telephone/active/org_role/permission/account fields; ไม่ reuse `Person` ที่ต้องมี active. Eligible pool ระบุด้วย behavior ไม่เพิ่ม discriminator/project metadata ลง wire
5. 200 response เสนอ **`anyOf`** legacy DirectoryPersonPage / ProjectMemberCandidatePage บน operation เดิม (สอง named schemasใหม่ → คาด **122 schemas / 89 routes**). ไม่ใช้ `oneOf`: หน้า `items:[]` ตรงทั้งสอง page schemas.
